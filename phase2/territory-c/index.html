Territory C · Phase 2 Creative Direction
Coverage Matrix
FM-04: Pass (strongest) Visual register: Systematic / dark grid
Concept

Your portfolio universe
is a matrix.
Every gap is visible.

Coverage Matrix treats the professional brand as a data visualization system — the visual identity IS the interface. Every name in scope is a cell. Every gap is flagged. Every event is a state change. The brand is the completeness of the system, and the system is always visible.

Where Territory A argues from precision and Territory B argues from provenance, Territory C argues from completeness. The grid is the claim: "coverage without gaps" is not a phrase here — it is the visual structure of every surface the brand occupies. An institutional buyer who opens the platform and sees a coverage matrix has been given, before reading any copy, a literal representation of the product's value proposition.

The grid is the identity. Every professional brand surface — the website hero, the conference backdrop, the enterprise deck — leads with a coverage matrix. The grid is not a decoration. It is data. Every surface where the Coverage Matrix grid appears is showing the actual state of coverage — or a representative sample of it. This connects the brand identity to the product's primary value claim at the pixel level.

Color System

Dark product register with a professional blue structural accent. Flare orange is reserved for flagged events — the ≤2% rule enforced by the semantic meaning of the color: if the entire coverage grid is orange, something catastrophic has happened. The blue-to-dark-navy range handles all structural and coverage elements. This is the furthest from Bloomberg's palette of any territory.

Bloomberg differentiation: Bloomberg's signature is amber/orange on near-black. Territory C uses blue-on-dark-navy. The surface color is a cooler blue-black (#0C0D10) versus Bloomberg's warm near-black. The structural accent is institutional blue (#2A4E92) — the color of the coverage state, not of the brand chrome. Flare orange appears only on flagged events. A Bloomberg Terminal and a Coverage Matrix interface are visually distinct from across the room: the blue tone, the grid structure, and the absence of Bloomberg's amber chrome produce a recognizably different aesthetic.
Competitor swap test — full six-competitor panel:
  • Bloomberg: Bloomberg Terminal uses warm near-black with amber/orange interface chrome distributed across navigation and data. Territory C uses cool blue-black (#0C0D10) with structural blue (#2A4E92) — a categorically different palette family. The coverage grid structure is also distinct from Bloomberg's data-density layout.
  • Brightwave: Brightwave uses dark, premium, expressive design. Territory C differentiates through: (a) structural blue rather than expressive dark-premium aesthetics; (b) the coverage grid as primary visual element (a functional data structure, not a design surface); (c) IBM Plex Mono dominant type (Brightwave uses a more expressive type system); (d) systematic/quantitative register vs. Brightwave's atmospheric premium register. The blue-navy palette is the primary swap-test differentiator — Brightwave does not use structural blue.
  • AlphaSense: AlphaSense uses a light, approachable research-platform design with modern SaaS sans-serif. Territory C's dark systematic grid is architecturally different — it reads as a monitoring instrument, not a search-and-discovery platform.
  • Hebbia: Hebbia uses a clean light workspace for document analysis. Territory C's blue-dark grid system is completely different in palette, register, and product visual metaphor.
  • Rogo: Rogo uses conventional institutional SaaS design. The coverage matrix as brand hero has no parallel in the institutional AI research space as of August 2026.
  • FactSet: FactSet uses blue-grey institutional data density. Territory C's blue-navy is palette-adjacent to FactSet's institutional blue, but the coverage grid structure (named-entity × time matrix with coverage states) is architecturally different from FactSet's data-terminal layout. The structural differentiation is the primary answer to the FactSet proximity question — if this territory advances, Phase 4 must ensure the grid structure is visually distinct enough from generic data tables that the FactSet swap test holds.
Token compliance note — proposed product register amendment: Territory C introduces a blue-tinted surface palette that deviates from lede-tokens.json v2.0.0 product register. Comparison: v2.0.0 product register specifies warm-neutral dark surfaces (#131210 / #1B1A16 / #242320 / #2C2B26). Territory C uses cool blue-tinted values (#0C0D10 / #131419 / #1A1C23 / #23252E) plus a structural blue (#2A4E92) not in v2.0.0. These deviations are intentional — the blue-tinted palette shifts the visual register from instrument-warm to systematic-cool, which is the territory's core creative argument. This requires Phase 4 authorization. If Territory C is selected, Phase 4 must either: (a) align the surface values to v2.0.0 warm-neutral product register (which would significantly change the territory's visual character), or (b) formally amend the product register token values and add structural blue (#2A4E92) as a named token for the professional brand system.

Logomark Direction

The Step logomark is recontextualized as the single illuminated cell in a coverage grid — the event node in a sea of covered cells. The wordmark uses IBM Plex Mono Bold. The logomark is a 3×3 grid with one Flare orange cell — the flagged event that proves the system is watching.

[Name] by Lede
3×3 grid mark: the orange cell = the event the system detected. All else covered.
Step at 16px on partner colors: The 3×3 grid mark at 16px is 5px per cell with 1px gaps. The Flare orange cell (center) is visible at this size as a distinct colored square. On light partner backgrounds, the grid mark uses blue coverage cells with an orange center. On dark backgrounds, same. The grid mark is the most scalable of any territory's logomark — at 16px it still communicates the coverage-grid concept. A monochrome version uses ink3 for coverage cells, and the flagged cell uses the highest-contrast ink available.

FM-04 Resolution — Editorial Identity Institutional Compatibility
VERDICT: PASS (strongest of all territories) — Territory C has no editorial identity whatsoever. It has no consumer-brand continuity. It has no editorial metaphors, no proofreader's marks, no Instrument Serif, no STET stamp. The Coverage Matrix is pure data visualization — the native language of quantitative institutional analysis. A bank procurement portal, a CTO's technical review, a compliance audit: Coverage Matrix reads as a monitoring system, which is what it is. FM-04 is not a risk in this territory — it is the departure point.

The tradeoff: Territory C has the strongest FM-04 clearance and the lowest visual continuity with the consumer Lede brand. The Endorsed House model tolerates this separation — professional and consumer are distinct brands. The question for Phase 3 is whether this much separation from the consumer brand is desirable, or whether the endorsement needs more visual weight than Territory C's IBM Plex Mono wordmark provides.

Strongest fit
A vigil is sustained monitoring — exactly what the coverage matrix represents. The matrix is a vigil rendered as a grid: 47 names watched, continuously, with nothing escaping notice. "Vigil by Lede" in IBM Plex Mono reads as systematic precision. The monitoring connotation is native to the Coverage Matrix concept.
Bearing
Good fit
Navigation's orientation reading. "Bearing by Lede" in IBM Plex Mono — the bearing is the system's output, the matrix's conclusion. Technical, directional, exact. Pairs with the grid-as-coverage metaphor cleanly.
Brief
Adequate fit
An intelligence brief is the output of the coverage matrix — what the grid produces when it flags an event. "Brief by Lede" in mono is clean. The word positions the brand as a reporting tool, which is accurate but less precise than the monitoring-instrument metaphor the coverage grid embodies. Works; not the strongest pairing.
